# CIP-0001: Refresh Decap CMS for the group site

## Status

- [x] Proposed - Initial idea documented
- [x] Accepted - Approved, ready to start work
- [x] In Progress - Actively being implemented
- [x] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete

## Summary

Bring the existing Netlify CMS admin (`admin/`) up to a working Decap CMS
deployment that can manage people, research themes, group projects,
publications, and especially Part II / Part III / MPhil available-project
briefs — including the new InfoTop fields — without requiring git fluency.

## Motivation

The site already has a substantial CMS configuration (`admin/config.yml`,
~1100 lines) that mirrors the Jekyll collections. Content editors are pointed
at https://mlatcl.netlify.app/admin/, but:

1. The UI still loads the deprecated `netlify-cms@^2` CDN package and Netlify
   Identity widget.
2. Live `/admin` currently returns HTTP 403 on both the Netlify mirror and
   GitHub Pages, so the editorial path is broken in practice.
3. New available-project frontmatter (`prerequisites`, and category values such
   as `mphil`) is not represented in the CMS schema, so editors would lose or
   mangle those fields if the UI were restored as-is.
4. Documentation still describes "Netlify CMS" and an older OAuth setup path.

We do not need a greenfield CMS. We need a refresh of what is already designed.

## Detailed Description

### Current state

| Asset | Role |
| --- | --- |
| `admin/index.html` | Loads Netlify Identity + `netlify-cms@^2` |
| `admin/config.yml` | GitHub backend; collections for settings, pages, posts, news, events, people, research, projects, publications, minijobs, availableprojects, opportunities |
| `admin/README.md` | OAuth / Netlify setup notes |
| Site README / `_minijobs/maintain_website.md` | Point editors to Netlify admin URL |

Backend is already `name: github` with `repo: mlatcl/mlatcl.github.io` and
`branch: main`. `local_backend: true` is enabled for local proxy editing.

The `availableprojects` collection already covers status
(`Available` / `Completed` / `Hidden`), categories, supervisors, related group
`projects`, FAQ fields, and body. Missing relative to current briefs:
`prerequisites`. Category options list `MPhil` while several briefs use
`mphil`.

### Target state

1. Decap CMS 3 loaded from the official CDN (`decap-cms`).
2. Working authentication for organisation members (GitHub OAuth via Netlify
   external provider, or an equivalent Decap-compatible gateway — decision in
   Phase 0).
3. Admin UI reachable at a stable URL (prefer restoring
   https://mlatcl.netlify.app/admin/ if the Netlify site is still the editorial
   mirror; otherwise document GitHub Pages `/admin/` once auth works there).
4. Schema aligned with current Markdown frontmatter, especially available
   projects and group projects.
5. Docs updated to say Decap CMS and to match the chosen auth path.

### Non-goals

- Replacing Jekyll or changing collection folder layout.
- Migrating content into a headless database.
- Building custom preview templates in the first pass (previews are already
  disabled in most collections).
- Solving GitHub branch-protection vs CMS direct-to-`main` pushes beyond a
  documented choice (editorial workflow optional later).

### Auth / hosting decision (Phase 0)

Pick one path before coding:

| Option | Pros | Cons |
| --- | --- | --- |
| **A. Keep Netlify mirror + GitHub OAuth provider** | Matches existing README; site already structured for it | Netlify Identity is deprecated; external GitHub provider must be verified; current 403 must be diagnosed |
| **B. GitHub backend with PKCE / client-side OAuth** | Less Netlify dependency | Needs a registered OAuth App and careful client-id handling |
| **C. DecapBridge (or similar gateway)** | Managed Identity replacement | Third-party dependency; org approval |

**Recommendation:** try **A** first (diagnose 403, confirm GitHub OAuth
provider on the Netlify site). Fall back to **B** or **C** only if Netlify
access control cannot be restored cleanly.

## Implementation Plan

### Phase 0 — Diagnose and decide (½ day)

1. Confirm whether https://mlatcl.netlify.app still deploys from
   `mlatcl/mlatcl.github.io` and why `/admin/` returns 403.
2. In Netlify: Access Control / Identity / Git Gateway / external GitHub
   OAuth provider — note what is enabled vs deprecated.
3. Confirm a GitHub OAuth App exists for the `mlatcl` org (or create one per
   `admin/README.md`).
4. Choose auth option A/B/C and record it in this CIP under Progress Updates.
5. Decide publish mode: keep direct commits to `main`, or enable Decap
   `publish_mode: editorial_workflow` if branch protection blocks CMS pushes.

### Phase 1 — Package and shell refresh (small PR)

1. Update `admin/index.html`:
   - Remove Netlify Identity widget unless Option A still requires it.
   - Load Decap CMS 3 from CDN, e.g.
     `https://unpkg.com/decap-cms@^3.0.0/dist/decap-cms.js`
     (pin a known-good minor version after smoke test).
2. Keep `admin/config.yml` backend as `github` unless the chosen auth path
   requires `base_url` / `auth_endpoint` overrides.
3. Smoke-test with `local_backend: true` (`npx decap-server` or the current
   proxy equivalent) against a local checkout.
4. Update `admin/README.md` title and login steps for Decap; keep OAuth
   screenshots only if still accurate.

### Phase 2 — Schema alignment for InfoTop-era content (same or follow-on PR)

1. **Available projects** (`availableprojects`):
   - Add `prerequisites` (markdown or text; matches YAML `>-` blocks).
   - Normalise category options to the values used in content and templates
     (`prtii`, `prtiii`, `mphil` / `MPhil`, `PhD`) — pick one casing and
     migrate existing frontmatter if needed so filters in
     `available-projects.html` stay correct.
   - Confirm `projects` relation still resolves new slugs
     (`information-topography`, `ai-adoption`, `interfaces`).
   - Optional: `year`, `month` if we want those editable (present on some
     briefs; currently omitted from CMS).
2. **Group projects** (`projects`): smoke-edit
   `information-topography` / `ai-adoption` / `interfaces` — ensure body,
   people, and publications relations round-trip.
3. **People**: confirm `alumni`, `end`, `institution` fields exist and match
   current person pages (add any missing fields used for leavers).
4. Do not strip unknown frontmatter on save — verify Decap does not drop
   keys absent from the schema when editing older briefs (spot-check Banerjee
   archive / Hidden entries).

### Phase 3 — Restore production admin access

1. Deploy Phase 1–2 to `main`.
2. Fix Netlify (or chosen host) so `/admin/` serves `admin/index.html` and
   `admin/config.yml` with HTTP 200.
3. Log in as an org member; create a throwaway Hidden available-project entry;
   verify the commit appears on GitHub; delete or re-hide it.
4. Update root `README.md` and `_minijobs/maintain_website.md` to say
   **Decap CMS** and to link the working admin URL.
5. Add a short "How to propose a student project" note pointing at the
   Available Projects collection and required fields (status, categories,
   supervisors, prerequisites, related group projects).

### Phase 4 — Optional polish (backlog after Closed)

1. Editorial workflow if branch protection is enabled.
2. Custom previews for `project-to-supervise` and `project-single`.
3. Media folder hygiene (`assets/images`) and larger upload guidance.
4. Consider whether GitHub Pages `/admin/` should be first-class or remain a
   Netlify-only editorial surface.

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| CMS save drops undeclared frontmatter | Spot-check Hidden/archive entries; add fields before broad editorial use |
| Branch protection blocks CMS commits | Use editorial workflow PRs, or a bot account with bypass, documented in README |
| Netlify mirror abandoned | Document GitHub Pages `/admin/` + Option B/C auth |
| Category casing breaks listing filters | Align CMS options with Liquid checks in `available-projects.html` in the same PR |

## Acceptance Criteria

1. An org member can open the documented admin URL, authenticate, and save a
   change that appears as a commit on `mlatcl/mlatcl.github.io`.
2. Creating or editing an Available project supports `prerequisites`, status,
   categories, supervisors, and related group projects without manual YAML.
3. Public site continues to list only `status: Available` briefs.
4. README / minijob docs describe Decap CMS and the live login path.
5. Local editing via `local_backend` still works for maintainers.

## Progress Updates

### 2026-09-20

CIP created from audit of the existing Netlify CMS setup and InfoTop content
gaps. No implementation started.

### 2026-09-20 (Phase 0 finding)

Login with GitHub from `/admin/` redirects to

`https://api.netlify.com/auth?provider=github&site_id=mlatcl.github.io&scope=repo`

and returns **not found**. Cause: with `backend.name: github`, Decap uses
Netlify’s OAuth proxy by default and sets `site_id` from the browser hostname.
On GitHub Pages that hostname is `mlatcl.github.io`, which is not a Netlify
site id. Auth only works if (a) the CMS is opened on a real Netlify site that
has a GitHub OAuth provider installed, or (b) `backend.base_url` points at a
working external OAuth client. Historical editorial URL
`https://mlatcl.netlify.app/admin/` currently returns HTTP 403, so Option A
needs Netlify site repair before it can work.

### 2026-09-20 (Phase 0 update)

Auth works when opening admin via Netlify
(`https://mlatcl.netlify.app/admin/`), not via GitHub Pages. Option A is
confirmed: keep Netlify as the editorial auth host; document that editors must
use the Netlify admin URL. GitHub Pages `/admin/` remains a non-login surface
unless we later add an external OAuth `base_url`.
